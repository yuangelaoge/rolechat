# 片刻 · 角色 AI 群聊

原生 Android 应用，Kotlin + Jetpack Compose。聊天与角色设置保存在本机，模型通过用户配置的 API 调用。最低 Android 8.0（API 26）。

## 使用

1. 从 [GitHub Releases](https://github.com/yuangelaoge/rolechat/releases/latest) 下载 `pianke-0.1.21.apk` 安装；已有交付安装包也可直接使用，可覆盖安装上一版。
2. 在「设置 → 硅基流动」填写自己的 API Key。地址默认 `https://api.siliconflow.cn/v1`。保存后可以获取模型列表，也可以直接手填模型 ID。
3. 在「角色」点击卡片上的「人设」或「模型」，直接进入对应配置；点击「聊天」开始单聊。编辑页按「人设／模型／行为／声音」分类，高级参数可展开。
4. 在「聊天」右上角创建群聊，将角色加入群中。聊天页右上角「⋯」展开会话菜单：「我的身份」填写自己在本群的名字和角色背景，每个群分别保存，单聊也可以单独设置；「群成员」加入／移除角色、修改参与概率与历史权限；「回复方式」进入智能接话／顺序／并发等回复规则。群设置按「基础／我的身份／成员／回复」分类，保存按钮固定在顶部。
5. 启用某角色的「双模型接续」，设置 A、B 模型与截断字数。B 的输出来源默认是「正文」，也可显式选择「思考字段兼容」。供应商设置选择相应的前缀协议。所有模型均可填写，没有验证白名单，也不会自动降级成提示词接话。
6. 在「设置 → 语音服务」选择「硅基流动」或「火山引擎」，启用语音。硅基流动复用已有模型服务的密钥；火山引擎填写独立语音凭据、资源 ID。保存后，长按消息选择「朗读消息」，或在群设置中开启自动朗读。需要过滤动作与旁白时，可在此页另外开启默认关闭的「提取对白后朗读」。

安装包和源码不包含测试密钥。密钥使用 Android Keystore 加密后在应用私有目录保存。聊天备份不包含密钥。

应用默认使用深色界面，包括聊天、角色、群设置、语音配置、弹窗和启动页。主页采用居中标题、右上角搜索和加号、连续会话列表。点击搜索图标后可按群聊名称、成员角色名或我的身份筛选，取消后回到完整列表；角色列表可按姓名、人设和模型名搜索。

聊天页采用单行居中标题、深灰与绿色气泡。头像和气泡顶边对齐；长消息在对侧头像区域前换行，左右消息都保留对侧头像列的空白；群聊角色的昵称紧贴气泡上方，自己的消息和单聊不重复显示逐条署名。点击消息详情仍能查看发送时的身份。@ 通过弹层选择，收起后与语音状态合用一行；停止本轮与发送共用按钮位置。长按角色消息可编辑、朗读、复制、查看详情、重新生成，或打开「思考内容（COT）」查看和复制；自己发的消息也可长按编辑。键盘弹出时输入框随之上移，阅读历史时流式回复不会自动抢回底部，可点「回到最新」继续跟随。

## 从编辑处重新继续（0.1.20）

长按自己的消息或 AI 回复 → 编辑消息 →「保存并发送」，会保留并修改所选消息，删除当前会话中它后面的所有消息，再从这里发起新一轮。删除按聊天显示顺序判断，同时间戳、导入时间异常也不会误删别的群。弹窗显示将删除的消息数量，不需要额外确认。

后续正文、A/B 分段、COT、语音前置处理及接话记录一同从本地数据中删除。当前会话的压缩前情清除，恢复使用保留的原文；正在生成和预取/播放的语音先停止，已丢弃回复不会继续占用角色冷却。其他会话的消息和设置保持原样。

如果删除范围包含 System 剧情指令操作，也撤销该范围内的指令修改。新记录保存修改前后的指令值，可以恢复到该节点的状态；0.1.19 的旧记录优先恢复最后一条保留的指令，若没有可恢复记录则清空。角色、世界观等当前配置不随聊天回退。

「保存」仍只编辑当前消息并保留后续聊天；「重新生成」仍只重做所选 AI 消息。保存并发送即使没有修改文字，也会删除后续内容并重新继续。

## System 剧情指令（0.1.19）

聊天页顶部的场记板按钮，或「⋯ → 剧情指令」，打开独立的 System 输入框。用于故事外纠正剧情、安排转场、调整人物行为；不必让自己扮演的角色说出这些要求。

- 「保存」更新当前指令，停止正在生成的旧回复和本会话朗读，下一次回复生效。
- 「应用并继续」更新指令并启动新一轮，遵循群聊现有的智能接话／顺序／并发设置与回复预算。
- 指令按会话隔离，持续生效到修改或清空。「清空指令」只停止继续施加这份要求，不撤回已经生成的剧情；清空聊天记录时也清除当前指令。
- A、B、场景角色和智能接话判断器均接收当前指令。它直接合入 API 的 system 消息，在故事设定冲突时优先于人设、世界观、旧前情与原话题。角色身份分工、结构化输出协议和调度可用性限制仍保留。模型实际遵循程度由所用模型决定。
- 聊天中留下独立的 System 操作记录，可选中文字复制。旧记录只供查看，后续模型上下文和前情压缩不再传递旧指令正文，避免修改或清空后被重新执行。当前指令独立于压缩记忆，不会被压缩掉。
- 指令与群聊配置、完整备份一同保存；旧数据无此字段时默认空白。

## 相册头像（0.1.18）

角色编辑页「人设」和会话设置「我的身份」均可从相册选择图片作为头像。选择后先预览，点右上角「保存」才生效；可以更换图片，也可以移除图片恢复原有文字头像。你自己的头像按会话分别保存，同一个角色的头像跟随角色使用。聊天消息、角色列表、成员列表和首页会话头像同步显示图片，场景消息保持原来的居中文字形式。

图片会在设备内居中裁为正方形、缩小并保存副本，不依赖相册原文件的长期访问权限。群聊配置导出与完整备份包含头像图片，导入其他设备后仍可显示；旧配置没有图片时继续显示原有头像。头像图片不发送给聊天模型。

## 连续朗读与语气衔接（0.1.17）

朗读采用提取对白、语音合成、音频播放三个独立步骤：播放当前一条时，可以提前合成下一条，并提取再下一条的对白。保留消息开始朗读时预约的顺序，双模型 A+B 仍作为一整条回复提取，提取关闭时保留流式文字合成。预取有数量和音频缓冲上限，停止朗读同时取消当前与预取任务，迟到结果不会恢复播放。

前置小模型除当前完整回复外，会参考同一会话、同一角色、同一音色的上一条有效朗读指令，不携带上一条原文、完整聊天历史或角色人设。指令帮助延续说话节奏、音量、语气和情绪强度；当前对白明确出现新的情绪或语气时，以当前内容为准，避免机械照搬。没有有效上一条时仍按当前回复独立处理。历史重读不会读取未来消息的指令，未播放就取消或失败的预取结果不会作为后续参考。

长按消息 → COT →「语音前置处理」可查看并复制本次参考的上一条朗读指令，以及本条提取结果和最终朗读指令；旧记录不会补造参考内容。已保存的自定义前置提示词保持不变，应用在有前条指令时补充声音衔接说明，用户仍可编辑自己的提示词。

提前准备可以减少相邻语音之间的等待，但不保证网络或合成服务较慢时完全无停顿；情绪衔接是文字指令引导，并非把上一条音频传给语音模型。豆包 2.0 继续通过原有独立语音指令参数接收本条 instruction，音色保持所选角色配置。

## 手动压缩与前情回顾（0.1.16）

聊天页右上角「⋯ → 手动压缩」。默认保留每位角色最近 20 条有权限查看的原文，将更早的聊天整理成前情；保留条数可设为 1–200。整理模型单独选择，可以获取模型列表；高级设置可修改压缩提示词或恢复默认。默认提示词保留文风、人物语气、情绪关系与未完约定，不含“尽量精简”的额外要求。

点击「生成前情草稿」后先预览，可切换角色、修改各自的前情，最后「确认使用」才影响后续回复。整理只发送该角色可见的聊天和有效旧前情，近期原文用于衔接与文风参考；不发送人设、世界观、思考或语音处理内容。每位角色分别整理，可能产生多次模型调用。关闭页面、取消、错误或不完整输出都不会自动替换原有前情。

原始聊天记录保留在本机，应用不会自动压缩。确认后，发言模型使用前情加保留原文；本轮原始要求、重新发送和当前回应对象仍保留原文，A、B 使用相同上下文。编辑被概括的旧消息或变更历史权限，会令旧前情失效并回退原文；可以重新整理，或选择「恢复完整上下文」。重试、重新生成不得读到原上下文范围之外的前情。

完整聊天备份包含已确认前情；群聊配置只导出压缩设置与模型服务依赖，不包含前情和聊天记录。删除会话、清空历史会同时移除前情。

## 头像与世界观

点击聊天中的 AI 头像或会话菜单里的成员头像，直接打开对应角色设置；按角色 ID 匹配，同名角色不会串人。返回或保存后回到原会话，保留输入草稿、@ 选择和滚动位置。点击自己的头像打开本会话「我的身份」，场景角色可点击署名进入设置。角色已离群但仍在角色库时可编辑，已删除时不跳转。

**会话世界观优先**：会话选了世界观，就使用它；没有选择时，才使用该角色自己的世界观。两份世界观不会自动合并，角色人设和本会话的真人身份始终一起加入。例如角色世界观是“校园”、群世界观是“都市”，实际使用“都市世界观 + 角色人设”。群设置的空选项因此显示「使用角色各自的世界观」。新单聊创建时会把角色当时的世界观选择复制到会话，之后可单独修改，不会随角色世界观切换自动同步。

## 会话管理与群聊导入导出

- 首页长按会话可「置顶／取消置顶」或「删除对话」；置顶会话排列在普通会话前。聊天页点击或长按顶部群名，或点击右上角「⋯」，也能使用这些操作。
- 「删除对话」会删除该会话及全部消息、思考记录和会话上下文；「清空聊天记录」只移除记录与上下文，保留会话、成员、世界观和自己的群内身份。两种操作都会停止当前会话的生成与语音，确认后不能撤销。其他会话不受影响，角色库与世界观库仍保留。
- 首页长按群聊或打开聊天页菜单，选择「导出群聊」保存 JSON 文件。文件包含群的全部设置、自己的群内名字和背景、成员及历史读取权限、角色的完整人设、模型及双模型配置、发言规则、消息样式、声音覆盖和关联世界观。包含相关模型服务的地址与协议设置，不包含任何聊天记录、思考、会话上下文、密钥或设备全局语音设置。
- 首页「＋ → 导入群聊」，或「设置 → 导入群聊配置」选择上述文件，直接创建新群，保留现有群聊和聊天记录。每位成员和世界观都创建独立副本；重名自动变为「小萱（2）」「小萱（3）」。已有数字后缀会继续递增，不会叠加括号。
- 导入时可复用地址和前缀协议完全相同的本机模型服务，否则创建新的服务配置，并需要自行填写密钥。角色原有的音色、语音模型覆盖会保留；全局语音接入使用当前设备的设置。
- 「设置」中的完整聊天备份仍用于整机数据迁移，包含历史并替换现有数据；它与不带历史、追加导入的群聊配置是两个独立入口。

## 编辑消息

长按自己的消息或 AI 回复 →「编辑消息」，可选择「保存」或「保存并发送」。消息的位置、ID、发送时间、署名、样式和上下文关联保持不变；后续对话，以及引用这条消息的重新生成，会读取更新后的文字。即使原角色已退出会话或被删除，历史 AI 回复仍可编辑。

保存有效修改会停止本会话正在进行的生成与语音，不会自动请求模型，也不会改写已经完成的后续回复。编辑 AI 回复后，会清空不再对应新正文的旧 A/B 分段、COT、语音前置处理记录和错误，并将该消息标为完成。需要模型重写时，可另行选择「重新生成」：它按这条消息原先的上下文范围从 A 开始，不把手动改写的正文当作 B 前缀。空白内容不能保存，取消不会修改原消息。

「保存并发送」原地保存后发起新一轮回复，也可以在正文不变时再次发送。自己的消息沿用原 @ 选择和会话回复规则；AI 消息在顺序／并发群聊中邀请其他角色接话，只有该角色时由它追加续答；智能群聊则重新判断接话对象，也可能等待真人或结束本轮。原消息不会复制为新消息，AI 消息也不会变成真人消息；此消息之后的历史全部删除，新回复从该节点继续。本轮会明确提示模型以重新发送的内容为接话依据；对新回复重试或重新生成时，也会恢复这次触发来源。即使该条消息早于成员入群时间，本次重发也仅开放这一条内容，其余历史仍按原权限隔离。

## 场景提示角色

- 在「角色」页点击「场景提示」快速创建，预填可编辑的场景叙述人设；也可在已有角色的「人设 → 消息样式」切换「角色对话 / 场景提示」。切换样式不会覆盖人设或模型。
- 场景角色照常配置世界观、模型、双模型接续、参与概率、冷却和声音，然后在群成员设置中加入群聊，也可以 @ 它回复。
- 场景消息使用居中的灰色文字与场景署名，不显示普通头像和气泡，适合环境变化、时间推进和旁白。长按仍可编辑、朗读、复制、查看详情、重新生成或查看 COT，失败仍可重试。
- 场景角色仍使用普通角色的模型调用与上下文权限，不是应用的真实系统命令。在智能接话中，若它能读取本轮原要求，会额外收到场景职责说明：落实真人明确授权的时间／地点过渡，避免重复已经发生的转场，不代写真人的行为、决定或其他角色的台词。每条新消息保存发送时的样式；之后改名、改样式或删除角色，不会改变历史样式。旧数据默认使用普通聊天样式。

## 智能接话（0.1.15）

进入群聊右上角「⋯ → 回复方式」，选择「智能接话（推荐）」，设置独立的接话判断模型后保存。已有群聊保留原模式，需要手动切换；新建群聊默认选智能接话，并以当前对白提取模型作为初始选择，之后两者独立保存。单聊保持原有回复方式。

每次需要决定下一位时，向判断模型提供本群成员 ID、名字、消息样式、当前能否被指定接话、真人名称、近期正文、本轮原始真人要求、已完成的相关场景消息及剩余发言次数。不传成员私有人设、世界观、真人背景、COT 或其他会话。判断模型关闭思考，返回接话对象、一句简短依据及与原要求的关系。它与对白提取模型是两个独立用途，可以选同一个模型，也可以分别配置。

- A 完整说完（双模型要等 A→B 整条完成），再判断由谁接话。例如 A 说“小萱，你怎么看？”且判断结果指向小萱，就直接安排小萱，跳过名单中其他角色。
- 明确把问题交给真人时等待你的输入；提到某人、引用某人说过的话或场景中出现名字，不等于邀请那个人接话。这些区别由判断模型依据提示词识别，不能保证所有含糊表达都判断正确。
- 没有明确对象的开放话题，从可主动发言的角色中按参与概率、冷却和本轮次数选择一位，随后再判断。不强制每个成员都发言。明确指定角色时优先点名，不随机改派；该角色冷却中或达到次数上限则停止。
- 通过输入框 @ 按钮明确选择多人时，先按成员顺序回应这些人，均以原真人消息为回应对象；之后再判断。手动 @ 绕过普通概率、冷却和角色次数限制，但仍受整轮发言上限限制。
- 默认最近 8 条消息、每轮最多自动回复 6 条，均可在群设置调为 1–20。达到总量上限、没有合适角色、服务超时或结果无效时停止，不切回固定名单补答。你发新消息、停止或编辑消息会取消旧判断，迟到结果不会继续发言。
- 发言模型会收到清晰的当前身份、其他成员身份和本次回应来源，降低把别人的台词当成自己身份的概率。原有入群历史权限继续生效；重发只开放明确重新发送的那一条。

长按被判断的真人或 AI 消息可看「接话安排」；顶部菜单「接话记录」打开最新一条。可查看、复制选择对象、简短依据、来源、模型、状态、时间和错误；新版判断还会显示“围绕原要求／举例说明／偏离原要求”。旧记录没有该字段时不补造判断。该记录不是模型的完整思考过程。编辑或重新生成相关消息会清除失效的记录；应用异常退出后，未完成判断恢复为取消。

接话提示词在群设置的高级设置中可编辑和恢复默认；输出协议保持固定。每次模型判断增加一次请求、费用和等待时间（最长约 20 秒）。群聊配置导出包含判断设置及对应服务配置，不包含判断记录、聊天或密钥；完整聊天备份包含判断记录。

## 保留原要求与场景推进（0.1.15）

群聊每一轮保留发起这一轮的真人要求。顺序、并发和智能接话都向发言角色明确指出这条原消息，正文仍留在原有真人历史项中；不把真人文字复制成系统提示词。当前回应对象与讨论目标分别处理：可以回应上一位的观点，但不能把其例子或提议自动当成真人的新任务。A→B 使用同一份要求与场景职责。历史权限保持不变，看不到原消息的成员不会获得其内容。

智能接话额外判断上一条属于正常讨论、相关举例还是偏题。举例后提示下一位将说明联系回原主题；偏题后提示下一位自然返回原问题，不撤回已展示的消息。合理分歧、相关补充和真人明确要求的举例或角色扮演发展不应判为偏题。判断模型返回的自由文字理由不会被拼进角色系统提示词。原要求独立传入判断请求，不会随“最近消息条数”被裁掉。

新的实质性真人消息开始新要求；“继续”“你们继续”等少量纯接续用语可以延续上一轮有效要求。编辑重发、重新生成及重试只恢复原上下文范围内、当前会话中的有效引用；新加成员不会借此读取其他旧消息。

例如真人说“就这样吧，你们两个先玩着，第二天喊我”：判断规则会要求按完整原话安排阶段，不能只看“就这样吧”就结束。它可安排两人简短互动，再用明确的角色选择调用场景角色描述次日，由人物叫真人后交回输入。当前剩余次数帮助它提前给转场与叫人留名额；已完成的相关场景另行保留，避免最近窗口过小时又跳一次“第二天”。这是故事时间，不是现实定时提醒。

场景角色必须已经加入本群。即使它的主动发言关闭、概率为 0，智能判断仍可以明确指定它；历史权限、冷却、角色次数和整轮上限继续生效。场景消息也占发言次数，程序不会为了完成剧情突破上限。没有可用场景角色或预算不足时，判断规则要求说明限制，不让普通人物冒充旁白。未得到真人授权时，角色自己的建议、引用和举例里的“明天”不能触发跳时。

这些改动提供持续的任务依据、场景记录和调度约束；理解自然语言、判定何时推进和生成合适内容仍由配置的模型完成，不能保证每次判断都正确。可从“接话安排”查看它为何继续或结束。旧自定义接话提示词继续保留，应用追加新版固定合同；解析兼容旧三字段结果，但该类结果不会显示新的话题判断。

## 回复规则

- **顺序**：角色按顺序生成，后面的角色可以看见此前已经结束的回复。
- **并发**：首批角色同时生成，使用开始时冻结的群记录，气泡顺序固定。它们不会看到彼此正在写的半句话。
- **顺序／并发互聊**：首批结束后，按配置追加有限条顺序回复。参与概率只在机会出现时判断一次。
- **@**：通过输入框旁的 @ 按钮选人。被选中角色绕过普通概率、冷却和普通人数上限；智能模式仍受整轮自动发言上限约束。
- **新消息**：立即打断旧轮次，保留已经展示的文字；不会为旧回复意外启动 B。
- **记忆隔离**：仅提供当前会话中该成员可见的消息。新成员默认不读取入群前历史，群设置可显式开启。
- **我的身份**：用户的名字和角色背景随当前会话进入系统提示词，与 AI 角色自身的人设分开。A、B 都读取本次回复的同一份身份设定。改名用于后续消息，已有消息保留发送时的名字。旧版数据会自动使用名字「我」和空背景，备份包含各会话的身份设定。

## A → B

A 的正文按 Unicode 字符边界截断；A 的思考内容不参与计数，不混入正文、语音、后续历史或 B 的续写前缀。达到截断点后立即启动 B，同时取消 A；不等待 A 正常结束或取消确认。截止点会尽量避开句末标点，但字数截断不能保证语义一定未完成。

A 提前结束、出错、长时间无正文或正文停滞，也会切换 B。A 没有任何正文时，B 从头回答。接续后的正文保存在同一条角色消息中，详情中可查看 A/B 分段、模型来源和中断原因。B 失败时重试只重做 B，保留 A 的前缀。

在「角色 → 模型」中，B 的「续写输出来源」默认选择正文，即读取 `content`，把 `reasoning_content` 单独保存为 COT。显式开启「思考字段兼容」后，仅 B 的请求固定开启思考，并只把 `reasoning_content` 当作正文；同时返回的 `content` 会忽略，避免两种输出混用。这些 B 文字参与前缀去重、正文超时判断、聊天历史和语音，不再重复保存为 COT。A 和其他角色不受影响，旧配置仍默认读取正文；每段消息记录生成时的输出来源。

硅基流动使用请求顶层 `prefix`；另提供末尾 `assistant` 和末尾 `assistant` + `prefix: true` 两种协议，便于接入其他兼容接口。若供应商把前缀一起返回，可开启「返回内容包含前缀」去重。实际模型拒绝前缀时显示原始服务错误，不静默改用其他模型。

## 重新生成与思考内容（COT）

- 长按角色消息，点击「重新生成」可在原消息位置从头重写。双模型从 A 开始，再按角色设置接续 B；使用当前角色、模型和世界观配置，以及该条消息原先保存的上下文消息范围，不包含后来的消息。
- 重新生成会替换这条消息原有的正文、A/B 分段、思考记录及语音前置处理记录；不会新增真人消息、触发其他角色跟答或改写已完成的后续消息。如果当前房间仍在生成，会先停止这一轮。角色已删除或移出会话时不可重新生成。
- 原来的「重试回复」保留：B 失败后的重试只重做 B，保留 A 的正文前缀和思考记录。
- 长按角色消息 →「思考内容（COT）」可查看本次接口实际返回的思考内容，按 A/B 模型分段，并显示生成／中断状态。可选中文字或点击「复制思考内容」复制全部。
- 通常思考内容只在该面板展示，与正文分开保存，不朗读、不加入消息预览或后续模型上下文。显式开启 B 的「思考字段兼容」是例外：B 的该字段已作为正文使用，不在 COT 面板重复展示。本地数据与聊天备份会保留实际记录的 COT；接口未返回、旧版本未记录或消息已手动编辑时，会提示没有记录，不会补造内容。更新前的旧消息无法补回先前未保存的思考过程。

## 语音

「设置 → 语音服务」选择当前引擎，所有角色共用这个接入服务。不同角色可配置各自的模型与音色。

### 音色试听

在「角色 → 声音」填写或选择音色后，点击「试听」，会用当前尚未保存的角色草稿朗读“你好，我是〔角色名〕，很高兴见到你。”，其中名字替换为草稿中的角色名。试听可随时停止，需要对应语音服务已配置有效凭据；即使全局「启用语音」没有打开，也可以试听。

试听直接调用语音服务，不经过对白提取模型，不新增聊天消息或改变上下文，也不会改变全局语音开关或自动保存角色。已有角色在豆包音色列表中点击「使用并保存」会立即保存该角色的音色，不保存其他人设或模型草稿；新建角色和手填音色仍需顶部「保存」。

### 语音前置处理记录

开启对白提取后，长按已朗读或正在处理的 AI 消息 →「思考内容（COT）」，顶部有固定的「聊天模型」和「语音前置处理」分页，不需要滚过 B 的长思考内容。点击「语音前置处理」可查看：小模型名称、处理状态、提取出的对白、语音指令，以及接口实际返回的思考字段。可展开小模型的原始输出，也可一键复制整份记录；失败时保留收到的原始内容和错误原因，方便检查提示词。处理完成表示对白提取成功，不代表语音服务已播放成功。

该入口始终显示处理状态，未有记录时明确说明尚无记录。符合朗读条件时，可直接点击「提取并朗读」，只重新处理和朗读当前消息，不重新生成 A/B；处理中不能重复点击。音色、语音凭据或提取凭据检查失败，也会保存失败原因供此处查看，不再只显示短暂提示。小模型处理中，聊天页保留进度与停止语音按钮。

COT 同时显示当前已保存的朗读音色，以及该次处理使用的资源、音色、时间和是否已调用小模型。配置更改不会篡改历史处理结果；两者不同会提示重新提取。可以直接在 COT 中「更换音色 → 使用并保存」，它按这条消息的角色 ID 更新，避免改到同名角色。随后点击「提取并朗读」使用新配置。

正式朗读开始时从最新保存角色读取音色，修正顺序群聊等待期间改音色却沿用旧角色快照的问题。保存新音色会停止该角色已有的待播音频；音色试听仍使用当前草稿。

只有小模型成功返回空对白时显示「没有可朗读的对白」。调用前检查失败显示「未调用模型／尚未提取」；模型或解析失败显示「未取得有效提取结果」。旧记录未保存调用标记时不猜测是否运行，也不会显示为已确认的空对白。

这些记录仅附属于对应消息，不会改写正文或加入聊天模型的上下文。修改消息、重新生成或重试时会清除旧记录；停止朗读或应用中断会记录取消状态，旧请求迟到的结果不会覆盖新内容。关闭提取、音色试听或未经过提取的旧消息不产生这份记录；对旧消息重新选择「朗读消息」才会生成新记录。完整聊天备份包含它，群聊配置导出不包含它。

### 可选的对白提取

「设置 → 语音服务 → 提取对白后朗读」默认关闭。开启后，选择一个已配置密钥的模型服务和提取模型，可自行填写小模型 ID，并编辑专用系统提示词。这份提示词只用于朗读前的处理，不会要求聊天主模型改变回复格式，也不会修改聊天正文。

开启时，应用先等待当前角色的一整条 A+B 回复结束，再发起一次独立提取请求。请求包含这条完整正文、专用系统提示词，以及可用时同会话同角色上一条有效朗读指令；不提供旧对白、完整群聊历史、角色人设或世界观。提取模型必须返回严格 JSON 对象，包含字符串 `text` 与 `instruction`，例如：

```json
{"text":"你回来啦，先坐下喝杯茶吧。","instruction":"用温柔、轻松的语气说。"}
```

`text` 是要朗读的对白，应保留原话，去掉动作、心理和场景描写；`instruction` 是可选语音指令，不需要时填空字符串。自定义提示词也须保留这个输出约定，不要添加代码块或 JSON 以外的说明。没有对白时返回空 `text`，应用跳过朗读；提取失败、超时、格式错误或输出被截断时，同样跳过本条，永不回退朗读原文。

两种语音引擎都只合成提取后的 `text`。`instruction` 仅在火山引擎资源为 `seed-tts-2.0` 时单独作为语音指令发送；其他资源及硅基流动不使用它，指令不会混进朗读文字。每条回复开启提取会增加一次模型请求；流水预取会与前条播放重叠，以减少排队等待。关闭后恢复直接按正文流式朗读。

### 硅基流动

1. 选择已保存密钥的硅基流动模型服务，复用其 API Base URL 和 API Key，无需再次填写。
2. 默认语音模型为 `FunAudioLLM/CosyVoice2-0.5B`，音色为 `alex`；可选 8 个预置音色，也可自由填写模型名称或完整 `speech:...` 自定义音色 ID。自定义音色须已在服务商处创建，本版不包含上传音频或克隆音色流程。
3. 在「角色 → 人设／模型 → 声音」填写该角色的语音模型、音色覆盖。留空沿用全局默认；火山引擎原音色配置会保留。
4. 开启群内自动朗读，或长按已有消息选择「朗读消息」。

使用 `/audio/speech` 的流式 PCM 输出，24 kHz、单声道、16 bit。正文按句末、适当停顿或长度上限分段提交；输入停顿时冲刷已收到的正文，音频边接收边播放。这是分段文字请求加音频流，不是双向 WebSocket 文字输入。短句之间的衔接和首声延迟取决于模型服务。全局语速可调为 0.25–4 倍。

### 火山引擎

使用豆包 V3 双向流式 WebSocket，正文增量进入同一个合成会话。支持 API Key，或旧版 App ID + Access Token。资源 ID 与音色须匹配；默认资源 `seed-tts-1.0` 和默认音色 `zh_female_cancan_mars_bigtts` 均可修改。

截图中的 `55000000: resource ID is mismatched with speaker related resource` 表示资源版本和音色不匹配。例如 `zh_female_cancan_mars_bigtts` 属于 1.0，不能直接与 `seed-tts-2.0` 配对。语音设置中的 2.0 快捷按钮会提示受影响的角色，保留已有角色音色；新建角色则根据当前资源选择默认音色。已知不匹配组合在试听和朗读联网前会被拦截，未知自定义 ID 仍可手动使用，不根据命名后缀猜版本。

「角色 → 声音 → 选择音色」支持按名称或 ID 搜索、只看当前版本适用音色。每个音色有独立的「试听」与「使用并保存」按钮。已有角色点击后立即保存该音色，即使随后返回也生效，不保存其他尚未提交的人设／模型草稿；新建角色仍需顶部「保存」。试听不会选用音色。应用内置 10 个经官方文档核对的目录条目，明确标识仅支持单向流的音色；应用采用双向流，该类音色不可用于试听。

需要拉取官方完整列表时，在「设置 → 语音服务 → 音色列表访问密钥」单独填写火山引擎 **Access Key ID 和 Secret Access Key（AK/SK）**，保存后回到音色选择页点击「刷新官方音色」。这是官方 `ListSpeakers` 的 IAM 鉴权，与语音合成用的 API Key / Access Token 不同，不能互填。密钥成对加密保存，不回显、不放入聊天备份。未配置 AK/SK 时仍能用内置目录和手填音色；列表刷新不会播放或合成语音。

刷新会分页获取 1.0、2.0 音色，并在全部成功后缓存结果。网络失败、权限错误或空响应会显示原因，保留原列表；重启可继续使用上次缓存。列表仅表示服务目录，具体账号是否已开通资源、音色权限和配额仍以合成接口返回为准。[官方 ListSpeakers 文档](https://docs.volcengine.com/docs/DoubaoVoice/ListSpeakers-LargeModelSoundListNewInterface?lang=zh)、[官方音色列表](https://docs.volcengine.com/docs/DoubaoVoice/Tonelist-1?lang=zh)。

启用对白提取并使用 `seed-tts-2.0` 时，非空 `instruction` 单独放入 StartSession 的 `additions` JSON 字符串，内容为 `{"context_texts":["提取出的语音指令"]}`。对白本身通过正常文本输入发送，不添加正文指令标签。接口依据：[豆包双向流式 TTS](https://docs.volcengine.com/docs/DoubaoVoice/WebSocketBidirectionalStreaming-V3?lang=zh)、[豆包 2.0 语音指令说明](https://docs.volcengine.com/docs/DoubaoVoice/DoubaoTextToSpeech20CapabilityIntroduction?lang=zh)。

凭据来自火山引擎：[登录控制台](https://console.volcengine.com/home)，[豆包语音 API Key 管理](https://console.volcengine.com/speech/new/setting/apikeys?projectName=default)。软件的语音设置页也有对应入口。

### 播放规则

角色按发言队列依次播放，同一角色的 A/B 正文进入同一缓冲与音色。常规思考记录不朗读；显式 B 兼容模式采用的思考字段已属于正文，也会进入该缓冲。启用对白提取后，缓冲中的完整正文先经过上述提取，再进入语音引擎。发送新消息、停止当前轮或编辑本会话消息会取消对应请求、清空待播内容并停止音频，包括尚未结束的对白提取。播放和服务错误不会终止文字聊天；无正文时不请求提取或语音合成。

## 代码结构

- `core/Models.kt`：角色、世界观、会话、模型配置、消息和生成片段。
- `core/ChatEngine.kt`：群聊调度、可见上下文、取消、超时和双模型接续。
- `core/TurnRouting.kt`：独立的智能接话请求、判断协议和记录。
- `app/network/`：流式文本协议、思考事件分离、供应商前缀适配。
- `app/data/`：Room 持久化、Keystore 凭据、备份恢复。
- `app/speech/`：独立对白提取、硅基流动 HTTP PCM 流、正文分段、豆包二进制协议与 2.0 语音指令及共享音频队列。
- `app/ui/`：中文原生界面。

## 当前范围

这是可安装的开发版本。角色、世界观、群聊、流式文字、A/B 接续与语音接口均有实际实现。没有云端同步或后台常驻服务；支持用户手动确认的前情压缩。长会话超过所选模型的上下文上限会显示接口错误，可手动整理前情或新建会话继续。数据库目前采用 Room 单条版本化快照存储，适用于第一版的本地使用，尚未优化大规模历史查询。进程被系统终止后，未完成消息会恢复为中断状态，可重试。

本次没有可用的独立火山引擎语音凭据及 IAM AK/SK，尚未验证真实列表权限、合成鉴权、2.0 音色和语音指令效果；0.1.12 已对 DeepSeek-V4-Flash 使用原始提示词做 3 次真实对白提取请求：带动作对白、无引号自然聊天、纯旁白均符合预期；仅验证这三个样例，不代表所有自定义提示词和角色文本。具体构建与测试结果见交付的测试记录。

## 群聊历史中的发言身份（0.1.21）

发给聊天模型的历史中，所有 AI 角色（含当前角色、其他角色与场景角色）的台词统一使用 `assistant`，并保留发送时的姓名标记；真人发言使用 `user`。智能群聊同时带角色 ID。模型 A/B 使用同一份带署名历史，模型 B 的未完成续写前缀保持原文，不额外插入署名。此规则也适用于旧聊天、重新生成和保存并发送，无需清空历史。
